# FloorTerminal 1.0.0

First public open-source release of the provider-neutral line-side reporting and
first-response touchscreen console.

## Raspberry Pi download

Download the application archive and its checksum from
[GitHub Releases](https://github.com/thesohampatel/floorterminal/releases):

```text
floorterminal-v1.0.0-linux-arm64.tar.gz
floorterminal-v1.0.0-linux-arm64.tar.gz.sha256
```

Verify the adjacent `.sha256` file before extraction, then verify the internal
`SHA256SUMS` before installation. Use the full
[installation guide](../prebuilt-raspberry-pi.md) for prerequisites and troubleshooting.

Built and locally acceptance-verified on 64-bit Raspberry Pi OS, Linux AArch64, with
PyInstaller 6.21.0 and Python 3.13.5 on Debian 13-based Raspberry Pi OS (Trixie).
Raspberry Pi 5 is the validated target. It is an application
bundle, not a bootable Raspberry Pi OS image.

## Install

```bash
sha256sum -c floorterminal-v1.0.0-linux-arm64.tar.gz.sha256
tar -xzf floorterminal-v1.0.0-linux-arm64.tar.gz
cd floorterminal-v1.0.0-linux-arm64
sha256sum -c SHA256SUMS
chmod +x install.sh floorterminal-launch floorterminal
./install.sh
sudo reboot
```

Read the complete [prebuilt Raspberry Pi guide](../prebuilt-raspberry-pi.md) before
deployment.

## Highlights

- Original FloorTerminal mark and launcher icon representing fault, report,
  coordinated response, restored production, and the operator's initiating touch.
- Touch-first arbitrary station and per-station failure selection.
- Local-first unplanned interruption and planned Engineering workflows.
- Multiple editable responder participation and repair timing.
- Independent response-record, messaging, directory, assignment, and asset capabilities.
- Provider-neutral Connector v1 with HTTPS/host policy, safe diagnostics, mappings,
  request budgeting, and remote idempotency requirements.
- Offline queue/retry, escalation, strict state recovery, retained structured logs,
  storage checks, protected Settings, responsive kiosk layout, and original sounds.
- Signature-verified offline USB software updates with managed version slots,
  administrator-authorized activation, one-touch rollback, and supervised automatic
  recovery from a version that cannot start.
- Audited source-free ARM64 bundle with MIT license, notices, SPDX SBOM, internal
  checksums, installer, autostart entry, and hardened user-systemd service.
- Public initial Settings access with a protected, masked, three-step password
  change that persists per installation across restarts and updates.

## Reliability and security

The first-release build also fixes managed direct-launch runtime paths, normalizes
and redacts remote HTTP error bodies, retains and revalidates signed staging across
restarts and before activation, rejects older update media, and provides an enforced
offline transport guard. CI uses immutable action pins and checks signed metadata
and source consistency. Distribution checks verify archive contents, signatures,
checksums, and the build-input fingerprint.

Version selection is deterministic across connected drives and versioned USB
collections. Approval is pinned to the reviewed payload, and failed/unconfirmed
versions are excluded from recovery. See
[multiple available versions](../update-user-guide.md#multiple-available-versions).

## Important deployment boundaries

- The standard initial Settings password is `admin@123` (public). Change it in
  Settings → System before production; the new installation-local password
  survives restarts/updates and disables the old password. No master override exists.
- External integration is disabled until a deployment-specific Connector v1 file is
  securely configured and acceptance-tested.
- A graphical Raspberry Pi OS session is required.
- This is not a PLC, machine controller, safety HMI, or certified safety system.
- Validate touch behavior, recovery, connector semantics, alarms/sound, and the full
  report-to-restoration workflow in a controlled environment before production.
