# v1.2.0 corrected distribution and existing installations

The maintainer authorized replacing the first v1.2.0 distribution without changing
its version number. This is an exceptional reissue, not the normal update policy.
The initial binary contained the current workflow code, but its compiled
Software Update → Version description still called it a development preview.
The corrected binary has the proper release description and full capability list.

The published tag now identifies the corrected source, and the release downloads,
signatures and checksums identify the corrected build. Always obtain the archive
and checksum together from the current
[v1.2.0 release](https://github.com/thesohampatel/floorterminal/releases/tag/v1.2.0).
Do not mix an older cached archive with a newly downloaded checksum.

## Identify an existing installation

Both distributions say **1.2.0**, so the version number alone is insufficient.
The corrected distribution's build ID is
`407f8f66-ca48-4976-913f-9ba610e9162f`. Its executable SHA-256 is:

```text
9c547e123aadb4c049c9eb04b7660fad41ef92d107eb2987803183fac5a450c5
```

The corrected installation archive SHA-256 is:

```text
ea381cc0fc9213fc9f8a831590d34d0d79b4b0c071f02611019acc5d51c76cab
```

The original executable's SHA-256 was:

```text
c11cc784d5f0f9d003d2e79d68e795d1e7607cba6786eaccc910afa1824038f0
```

On the kiosk, inspect the installed executable and its notices:

```bash
sha256sum /opt/floorterminal/floorterminal
grep 'Build ID:' /opt/floorterminal/SOFTWARE_INFORMATION_AND_NOTICES.txt
```

Compare with the corrected executable hash in the current archive's `SHA256SUMS`
and the build ID in its notices. Do not rely only on the green update indicator:
that compares semantic versions, not same-version replacement builds.

## If the old v1.2.0 is already running

Use a planned maintenance window and an authorized administrator. This is a local
reinstall of the application bundle, **not** a USB update or operating-system image.
The application and its data belong to the kiosk login account; run the installer
from that account, not from an unrelated administrator's home directory.

1. Finish every group's active response. Wait until saved work is synchronized or
   deliberately reconciled. Confirm the kiosk is idle. Do not remove state files.
2. Download the current installation archive and its `.sha256` file; verify and
   extract into a new empty folder as in the [installation guide](../prebuilt-raspberry-pi.md).
   Never extract it over `/opt/floorterminal` or over deployment configuration.
3. Stop the supervised app before replacing its executable:

   ```bash
   systemctl --user stop floorterminal.service
   pgrep -ax floorterminal
   ```

   The second command must show no running app. If another launcher keeps it alive,
   stop that launcher through the site's maintenance process before continuing.
4. Back up the **entire deployment root**, including all connectors, Settings access,
   state, records and update history. This archive contains private data; keep it
   on protected storage and never upload it to GitHub:

   ```bash
   umask 077
   mkdir -p "$HOME/floorterminal-private-backups"
   sudo tar -C /opt -czf - floorterminal > "$HOME/floorterminal-private-backups/before-v1.2.0-reissue-$(date +%Y%m%d-%H%M%S).tar.gz"
   ```

   Verify the backup can be read and that there is enough free space before proceeding.
5. In the freshly extracted, checksum-verified installation bundle, run:

   ```bash
   ./install.sh
   systemctl --user start floorterminal.service
   ```

   The installer preserves existing deployment configuration and the default
   connector, leaves other connector/state/history/password files in place, and
   replaces the same-version executable and release notices. It resets the
   supervised boot marker to confirmed; this manual reinstall does not perform
   the signed USB updater's probation or data migration. Keep the backup: normal
   version-slot rollback cannot restore the overwritten original 1.2.0 binary.
6. Compare the installed executable checksum and build ID to the extracted bundle.
   Confirm Information shows 1.2.0, the Version panel has no development-preview
   wording, the line/groups/crew are correct, Settings still accepts the site's
   password, and saved operational data remains present. Perform site acceptance
   before returning the kiosk to service.

If any verification fails, keep the service stopped and use the site's controlled
backup-recovery process. Do not delete state, reuse a modified unsigned executable,
or downgrade through an incompatible release to bypass the version guard.

## New installations and earlier versions

New installations use the current installation archive. Earlier supported releases
use the corrected signed USB package, with the existing idle-state, signature,
compatibility and health checks. The reissue does not install itself remotely or
silently change any running kiosk.
