# FloorTerminal 1.2.1 — kiosk interaction refinements

Released **4 November 2026**. This patch refines the operator interface without
changing incident timing, station/group scope, connector schema or authorization.
Existing v1.2.0 installations can use the normal signed USB upgrade; this is a
new version, not a replacement of the v1.2.0 release.

[Download v1.2.1](https://github.com/thesohampatel/floorterminal/releases/tag/v1.2.1) ·
[Native interface screenshots](../images/README.md) ·
[Test evidence and measured limits](../verification.md).

## Operator-facing changes

- The main-screen clock always shows 24-hour `HH:MM:SS` in a fixed-width digital
  face. It has its own header card on wide screens and its own status-row card on
  narrow screens. Long line names and notices abbreviate within their own space.
  The clock follows the kiosk operating system's local time/time zone; it does not
  change duration measurement, delivery scheduling or security clock checks.
- The touch keyboard separates letters/numbers from symbols using **#+= / Letters**.
  **ABC / abc** changes letter case. **Delete** removes one character. QWERTY rows
  are retained where ten touch keys fit, and split into balanced rows on narrow
  screens. Compact-height layouts use explicit key pages rather than tiny targets.
  All ASCII punctuation remains available; physical keyboards still work.
- Failure choices use equal-width/equal-height cards on each page. A partial final
  row is centred without stretching its cards. **All**, **None**, **Find** and page
  navigation occupy a separate toolbar. Optional selection, automatic **Others**,
  per-station catalogues and multi-station/group incident scope are unchanged.
- Pressed controls compress inside their original touch target and briefly
  acknowledge release. Touch contact is shown even on background space, but that
  is not a claim that an operation succeeded: completion/error notices remain the
  authority. Dragging off a button cancels it as before. No per-button continuous
  animation loop or external graphics dependency is introduced.
- Information has **Overview**, **License** and **Safety** tabs. Creator/contact,
  MIT terms, exclusions, warranty and deployment responsibilities remain available.
  Software Update separates installed/latest versions when space allows and sizes
  its action footer to the actual available actions. Signature verification and
  administrator authorization are unchanged.
  Text paging keeps section headings with their explanations where space permits.

## Choose the home-screen support buttons

Open protected **Settings → Connector** (called **Connection** on compact screens).
Find **Home support button 1**, **2** and **3**. For each slot:

1. Choose **Show this button** to enable it, or turn it off.
2. Enter a short **Button label**, such as Maintenance team, Quality technician or
   Production supervisor.
3. Enter its exact **Chat / person destination**, or select a directory suggestion.
4. **Save all settings**. These changes take effect without a rebuild.

These are message shortcuts, not incident-assignment teams. Pressing one does not
create an incident, stop a station, change crew or change automatic activity chats.
The existing support message template receives the configured label as
`{department}` and still includes selected stations/groups/failure context.

Disabled slots are omitted. An enabled slot without a destination or messaging
capability is shown as not set up. On very short screens the **Support** entry
opens the same configured choices. Labels are limited to 48 printable characters,
destinations to 120. Use distinctive short labels; long labels wrap/abbreviate.

Existing `support_buttons: null` (or a missing key) means use the original
Engineering/Quality/Production labels and their existing chat-name settings.
Saving the new Settings editor stores explicit shortcut values. Thereafter,
automatic chat routing and manual shortcut destinations are edited independently.
Queued support messages retain the destination/text captured when requested;
editing a shortcut cannot reroute a previously saved message.

See [configuration](../configuration.md) for JSON, [failure reasons](../failure-reasons.md)
for selection behavior and [settings access](../settings-access.md) for authentication.

## Installation and upgrade

New installations download `floorterminal-v1.2.1-linux-arm64.tar.gz` and its
`.sha256` sidecar. Existing kiosks download
`floorterminal-v1.2.1-update-linux-arm64.tar.gz` and its `.sha256` sidecar.
These are application bundles, not operating-system images. The Linux ARM64
binary targets 64-bit Raspberry Pi OS based on Debian 13 (glibc 2.41).

Follow [installation](../prebuilt-raspberry-pi.md) or the
[signed USB update guide](../update-user-guide.md). Back up deployment data
privately, finish every active group response and resolve pending delivery first.
Keep the kiosk's own configuration, connectors and Settings credentials; never
overwrite them with the blank templates from a fresh-install archive. After
upgrading, allow the normal two-minute GUI health check to finish.

New installations use the public bootstrap password `admin@123`; change it in
Settings before production use. Existing installation passwords are preserved.

## Compatibility and validation boundaries

No connector contract, credential, incident-state or update-signature format changes
are needed. `support_buttons` is an additive configuration field. Older software
does not display custom shortcuts; retained configuration extensions allow a return
to compatible newer software without losing them. Normal update compatibility
checks still apply; do not downgrade during active or pending work.

Offline checks use disposable runtime directories and denied network connections;
no site's connector, credentials or response records are used. Native screen tests
and short rendering samples are not a months-long soak, external API certification
or a guarantee that all device/display combinations behave identically.

The Pi build passes **755 offline tests with zero skips**. Native compiled GUI,
restart recovery, real v1.2.0 upgrade/rollback and source/signature/archive checks
are recorded in [verification](../verification.md). The gallery contains 135
fresh source-matched captures, including animations. Site commissioning remains
necessary; this is reporting software, not a machine safety controller.
