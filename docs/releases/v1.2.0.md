# FloorTerminal 1.2.0

This version focuses on independent production groups, local-first reporting and
a responsive kiosk interface. Download only assets actually published in
[GitHub Releases](https://github.com/thesohampatel/floorterminal/releases); this
document alone is not a release announcement.

## Operator-facing changes

- **Independent groups:** configure stations as production cells or groups, with
  either group-only or whole-line stop propagation. Other groups keep running;
  each active response retains its own stations, crew, timing and delivery state.
  The map shows group boundaries and status-specific conveyor movement.
- **Operator self-fix:** report a minor stoppage, attempt an operator-permitted
  remedy, and resume production or hand the same incident over to Engineering.
  This does not authorize maintenance or replace site safety procedures.
- **Flexible failure reasons:** each station has automatic **Others**, plus any
  number of user-defined reasons within documented storage limits. Adaptive
  pages/search preserve multi-selection; a reason is optional when reporting.
- **Short touch paths:** the routine report path takes 2–3 taps, and cached-name
  arrival, single-person crew edits and confirmed completion take two. Additional
  station/person selections, notes and search remain optional extra interactions.
- **Saved team members:** crew pickers use a private persistent roster. Refresh
  runs after midnight when idle, or from **Settings → Connection → Refresh team
  members**. Outages do not erase verified names or change an open picker.
- **Adaptive kiosk pages:** main screen, protected pages, crew selection and
  fullscreen Settings reflow for landscape, portrait and compact displays.
  Buttons retain touch feedback; Settings reveals a complete form behind a loading
  cover instead of exposing controls as they are constructed.

## Reliability and connection behavior

Physical line decisions save locally before external delivery. A bounded durable
queue resumes after restart and handles connectivity loss, rate limits and server
cooldowns without network work on the GUI thread. Request budgets are configurable
in Settings. Uncertain non-idempotent writes are held for protected review rather
than blindly duplicated. A service must actually implement any deduplication
guarantee declared in its connector.

Connector schema remains **1**. Optional mappings support group assets/locations,
structured station diagnoses, explicit team/person assignments and original event
timestamps. Missing capabilities disable only their dependent features. No real
third-party service calls are part of release verification; complete
[connector commissioning](../connector-commissioning.md) for your account.

Private incident history supports standalone reporting and future exports.
Automatic device care bounds old history/log retention according to storage health;
it never removes pending deliveries or incident-recovery state to free space.

## Installation and upgrading

The Linux ARM64 installation bundle is an application, **not an OS image**:

```text
floorterminal-v1.2.0-linux-arm64.tar.gz
floorterminal-v1.2.0-linux-arm64.tar.gz.sha256
```

Existing kiosks use the separately signed USB package:

```text
floorterminal-v1.2.0-update-linux-arm64.tar.gz
floorterminal-v1.2.0-update-linux-arm64.tar.gz.sha256
```

Follow [installation](../prebuilt-raspberry-pi.md) or the
[USB update guide](../update-user-guide.md). Back up deployment data privately,
finish every active group response and resolve pending synchronization before
upgrading. Keep all connector files and the local Settings password in place;
never replace them with the blank release template. New installations use the
public bootstrap password `admin@123`, which must be changed before production use.

The new updater checks configuration, connectors and saved state before switching,
retains bounded private checkpoints and verifies a healthy GUI during probation.
Reporting waits during that maintenance window. Compatible schema-1 connector
files need no manual rewrite just to upgrade the application.

**Rollback is conditional, not universal.** An older binary may not understand
new groups, failure catalogues or saved-state fields, including the roster retry
metadata. Unsupported downgrades are refused without deleting data. Keep the newer
version or use a reviewed lossless migration; do not clear recovery state to force
an older version to start. See [data compatibility](../update-data-compatibility.md).

## Verification and deployment boundaries

The 3 November 2026 candidate passes **727 offline tests, with no skips, on Pi 5**
and achieves **88% application statement coverage**. Its compiled ARM64 GUI and
signed installation/update artifacts pass their acceptance checks. See
[dated verification evidence](../verification.md) for native-panel measurements,
build acceptance and remaining limitations, including first-open Settings latency. Automated
offline fixtures cover rendering, workflows, persistence, queues, update security
and connector wire contracts. They do not establish live-service compatibility,
physical glove usability, uninterrupted multi-month operation or absence of every
possible defect.

The validated target is Pi 5 on 64-bit Raspberry Pi OS / Debian 13 with a graphical session.
Build-host ABI details are in the release notices/SBOM; an older OS may require a
native rebuild. Commission cooling, power, storage, touchscreen calibration,
network restrictions and backups at the site. FloorTerminal is not a safety-rated
controller or a substitute for guarding, emergency stops or lockout/tagout.
