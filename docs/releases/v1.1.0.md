# FloorTerminal 1.1.0

A reliability, clarity, and display-quality release of the line-side reporting and
first-response touchscreen console. It is a drop-in upgrade from 1.0.0:
configuration, connector files, saved workflow state, and audit logs are kept.

## Raspberry Pi download

Download the application archive and its checksum from
[GitHub Releases](https://github.com/thesohampatel/floorterminal/releases):

```text
floorterminal-v1.1.0-linux-arm64.tar.gz
floorterminal-v1.1.0-linux-arm64.tar.gz.sha256
```

Terminals that already run 1.0.0 can instead install the signed USB update package,
`floorterminal-v1.1.0-update-linux-arm64.tar.gz`, as described in the
[update guide](../update-user-guide.md). The previous version stays installed for
one-touch rollback.

## Fixed

- Completing a repair, and starting or releasing planned Engineering work, is saved
  reliably. Version 1.0.0 could reject these transitions with "Persisted state
  contains unsupported fields" and leave the screen showing Production running
  while the saved state still said a repair was active.
- A save that cannot be completed restores the last saved state in place, and the
  screen explains which operation failed. One rejected value no longer makes later
  station selection, crew confirmation, synchronization, or support calls fail.
- The line release is one atomic transition that also queues the response-record
  completion, the asset Online state, and the completion notifications. A restart
  or outage at any point leaves those updates queued for retry.
- If a release could not be saved, confirming it again keeps the original release
  time, so the recorded duration and micro-stop classification do not change.
- Completion chats state what actually synchronized: "DONE update queued" while
  pending, and "DONE not confirmed" after expiry, rejection or queue eviction.
  Successful delivery evidence survives delayed messages and restarts. Manual
  synchronization no longer implies expired or abandoned entries were delivered.
- Release time is captured on the affirmative confirmation touch rather than when
  the dialog opens, and stays stable if the worker runs later.
- A queued DONE for one response record is no longer overwritten when the next
  repair begins.
- Team and chat names can be typed in Settings even when a directory is loaded.
- Save and Cancel stay visible in Settings on 800 x 480 panels.
- Every documented message-template placeholder formats without error.

## Added

- Durable, bounded queues for response-record comments and status changes, lifecycle
  chats, and support calls. They are rescheduled from the connector's rate-limit
  delay, expire when stale, and are audited when abandoned.
- Asset Offline and Online notes list the affected stations, the reported failure
  types, and the operator's own description, without wall-clock timestamps.
- A persistent error panel that names the failed operation and the saved line
  status.

## Display quality

- Anti-aliased rounded controls, cards, and circles on Raspberry Pi and other X11
  displays, drawn from cached pre-rendered shapes at unchanged frame cost.
- Text is pinned to the 96 DPI design scale on X11, so a panel that reports its
  physical size no longer enlarges labels relative to their controls.
- A flat, touch-sized Settings theme with drag scrolling on every tab.

## Compatibility

- No configuration or connector changes are required.
- An idle 1.1.0 state file contains only fields that 1.0.0 accepts, so rolling back
  while Production is running resumes cleanly. Rolling back during an active
  planned-work event or with updates still queued makes 1.0.0 stop at its
  state-recovery screen rather than guess; complete the work or let the queue
  drain first.

## Verification

The native ARM64 build was made and verified on Raspberry Pi 5 with Raspberry Pi
OS 64-bit (Debian 13/Trixie), Python 3.13.5 and Tk 8.6. All 410 offline tests pass
with zero skips and 83% measured coverage. The compiled executable also passed
main-screen, Information and protected Settings checks at 800×480 and 1600×960.
The source touchscreen sweep additionally covers 1280×800 and 1920×1080.

The installation and signed USB update archives include checksums, licensing
notices and dependency information. No customer connector, credentials, logs or
saved workflow state are distributed. See [release verification](../verification.md)
for the checks and site-commissioning boundaries.
